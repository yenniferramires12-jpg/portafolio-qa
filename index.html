DEF-01 — Dos imágenes devuelven error 404 en la página de imágenes

Severidad: Media
Pasos para reproducir
1. Abrir la página /broken_images del sitio demo. 2. Observar que dos imágenes no cargan. 3. Comprobar las URL con curl.
Resultado esperado
Todas las imágenes referenciadas existen y devuelven HTTP 200.
Resultado real
asdf.jpg y hjkl.jpg devuelven HTTP 404.
Evidencia
Códigos de estado obtenidos con curl: asdf.jpg → 404, hjkl.jpg → 404, img/avatar-blank.jpg → 200.

Nota: es una página de práctica diseñada para este ejercicio; el hallazgo demuestra la detección, no un fallo de un producto real.

DEF-02 — Tres imágenes sin atributo alt

Severidad: Media
Pasos para reproducir
1. Abrir la página /broken_images. 2. Inspeccionar las etiquetas img.
Resultado esperado
Cada imagen tiene un atributo alt descriptivo para lectores de pantalla.
Resultado real
Tres imágenes no tienen atributo alt: asdf.jpg, hjkl.jpg e img/avatar-blank.jpg (esta última sí carga, HTTP 200).
Evidencia
Fragmentos HTML sin atributo alt en los tres img.

DEF-03 — Casillas de verificación sin etiqueta asociada

Severidad: Media
Pasos para reproducir
1. Abrir la página /checkboxes. 2. Inspeccionar el formulario.
Resultado esperado
Cada casilla tiene una etiqueta label asociada, para que sea identificable con lector de pantalla y pulsable por su texto.
Resultado real
Las dos casillas no tienen id ni label; el texto «checkbox 1» y «checkbox 2» es texto plano fuera de la etiqueta.
Evidencia
<input type="checkbox"> checkbox 1 y <input type="checkbox" checked> checkbox 2.

DEF-04 — Lista desplegable sin etiqueta asociada

Severidad: Media
Pasos para reproducir

Resultado esperado
El desplegable tiene una etiqueta label asociada a su id.
Resultado real
El elemento <select id="dropdown"> no tiene ninguna etiqueta label asociada en la página.

Fragmento <select id="dropdown">, sin elemento label en la página.

DEF-05 — Campo numérico sin etiqueta ni identificador

Severidad: Media
Pasos para reproducir
1. Abrir la página /inputs. 2. Inspeccionar el campo de entrada.
Resultado esperado
El campo tiene etiqueta asociada e identificador, para que sea operable y anunciable.

El campo es <input type=number>, sin id, sin name y sin etiqueta asociada.

DEF-06 — Orden de encabezados incorrecto en varias páginas

Severidad: Baja
Pasos para reproducir
1. Abrir las páginas /login y /forgot_password. 2. Revisar la jerarquía de encabezados. 3. Repetir en /checkboxes, /dropdown, /inputs, /broken_images y /tables.
Resultado esperado
Los encabezados siguen un orden sin saltos (h1 → h2 → h3) y cada página tiene un h1.
Resultado real
/login y /forgot_password pasan de h2 directamente a h4 (se omite h3); cinco páginas inician su contenido en h3, sin h1 ni h2.
Evidencia
Secuencias de encabezados extraídas del HTML: login y forgot_password = [h2, h4]; checkboxes, dropdown, inputs y broken_images = [h3]; tables = [h3, h4, h4]. La página principal sí ordena h1 → h2 correctamente.

Mi metodología para reportar un defecto

  1. Título claro: qué falla y dónde, en una frase.
  2. Severidad: qué tanto afecta al usuario y al negocio.
  3. Pasos para reproducir: numerados, desde el inicio, sin pasos implícitos.
  4. Resultado esperado contra resultado real: qué debería pasar y qué pasó en realidad.
  5. Evidencia: capturas, fragmentos de código o códigos de estado reales.
  6. Entorno: fecha, herramienta, navegador o dispositivo y versión, para que el hallazgo sea repetible.

Antes de reportar, verifico que el defecto sea reproducible y que no esté duplicado. Si un comportamiento es propio del diseño de la aplicación, lo registro como observación y no como defecto.
